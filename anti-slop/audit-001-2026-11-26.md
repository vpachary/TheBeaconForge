## Numbered Findings List

### 1. [HIGH] Rule R-02 (Copywriting — Hard Gate)
- **Location:** `index.html` (lines 6, 14, 430, 455–457) & `components.css` (line 185)
- **Violation:** Em dash (`—`) characters present in text and content:
  - Line 6: `<title>The Beacon Forge — Independent Web Design & Engineering Studio</title>`
  - Line 14: `<meta property="og:title" content="The Beacon Forge — Independent Web Studio">`
  - Line 430: `<input type="hidden" name="_subject" value="New Client Inquiry — The Beacon Forge">`
  - Lines 455–457: `<option>01 — Essential Website ($1,000)</option>`
  - `components.css` line 185: `.deliverables-list li::before { content: "—"; }`
- **One-line reason:** Rule R-02 strictly forbids em dashes (`—`) in favor of colons, commas, periods, or standard hyphens/bullets.
- **Remediation:** Replace with colons (`:`), pipes (`|`), or standard bullet characters.

---

### 2. [HIGH] Rule R-39 (Interaction Affordances — Hard Gate)
- **Location:** `style.css` (Base layer)
- **Violation:** Missing explicit global interactive cursor affordances.
- **One-line reason:** Rule R-39 requires `cursor: pointer` set in the base layer on all enabled controls (`a[href]`, `button`, `select`, `label[for]`) and `cursor: not-allowed` on disabled states.
- **Remediation:** Add unified interactive pointer rule to `style.css`:
  ```css
  a[href], button, select, label[for], summary { cursor: pointer; }
  button:disabled, input:disabled, select:disabled { cursor: not-allowed; }
  ```

---

### 3. [LOW] Rule R-21 & R-34 (Theme Selection — Quality Locks)
- **Location:** `index.html` & `style.css`
- **Violation:** Dark mode is hardcoded via `data-theme="dark"` with no light mode toggle.
- **One-line reason:** Rule R-21 allows a fixed dark theme if justified by brand character, but recommends a functional toggle if user preference should be supported.
- **Remediation:** Formally record the dark atelier identity in `DESIGN.md` under R-21, or implement an optional light mode palette override.
